# Upgrade merge modes

Per-file declaration of how the upgrade phase reconciles a stub against an existing file in the target. Five modes:

| Mode | Behaviour | Used for |
|---|---|---|
| `replace` | Whole-file overwrite (with overwrite prompt unless `--force`). Audit flags OUTDATED on any diff. | Files we fully own. |
| `managed-block` | Patch only inside a delimited block. Audit flags OUTDATED only on drift inside the block. | `.gitattributes` (inside package-boost's block) |
| `append-only` | Add missing lines; never remove or reorder existing. Audit flags MISSING per line we expect but is absent. Never flags OUTDATED for extra lines. | `.gitignore` |
| `merge-keys` | Surgical JSON/YAML key insert; only touches listed keys. Audit flags MISSING per key. Never flags OUTDATED for whole-file diff. | `composer.json` |
| `notify-only` | User owns the file after bootstrap. Audit informs of drift but never flags OUTDATED automatically. Upgrade never auto-writes. | `phpstan.neon.dist`, `rector.php`, `pint.json`, `phpstan-baseline.neon` |

## Per-file mapping

### `replace`

- `.editorconfig`
- `.mcp.json`
- `.github/workflows/phpstan.yml`
- `.github/workflows/pint-check.yml`
- `.github/workflows/rector-check.yml`
- `.github/workflows/update-changelog.yml`
- `.github/dependabot.yml`
- `tests/Pest.php` (pest-only; replaced when test-framework is pest)
- `phpunit.xml` (phpunit-only)
- Category-specific run-tests workflows: `.github/workflows/run-tests.yml` — exception: a matrix aligned to the repo's `require.php` floor (cells below the floor removed, and/or cells added above the stub's 8.3/8.4 coverage — e.g. no `8.3` cells plus an `8.5` cell on a `^8.5` floor) is correct, not OUTDATED; the stub matrix assumes the default `^8.3` floor
- `testbench.yaml` (laravel-package only)
- `workbench/app/Providers/WorkbenchServiceProvider.php` (laravel-package only)
- `extension.neon` skeleton (phpstan-extension only; the `services:` block is user-owned past bootstrap — but the file structure is `replace` and the user is expected to edit only the inner blocks)
- `config/config.php` skeleton (rector-extension only; same pattern)
- `boost.json` (laravel-project only)
- `.lpv` (php-package only)

### `managed-block`

- `.gitattributes` — see `gitattributes-managed-block.md` for the contract.

### `append-only`

- `.gitignore` — add the lines we own that are missing. Existing user lines stay. Extra user lines are fine. Audit only flags MISSING.

### `merge-keys`

- `composer.json` — patch these keys:
  - `scripts` (entire block; insert missing per `composer-scripts.md`)
  - `extra.laravel.providers` (laravel-package only — insert the ServiceProvider FQCN if missing)
  - `extra.phpstan.includes` (phpstan-extension only — insert `["extension.neon"]` if missing)
  - `extra.rector.includes` (rector-extension only — insert `["config/config.php"]` if missing)
  - `config.allow-plugins` (insert missing plugin entries per `version-defaults.md`)
  - `config.sort-packages` (set to `true` if absent)
  - `autoload-dev.classmap` (phpstan-extension only — insert `tests/Rules/stubs/` if absent and the dir exists)

### `notify-only`

- `phpstan.neon.dist` — user actively tunes parameters per project; auto-overwriting would destroy work.
- `phpstan-baseline.neon` — generated by `phpstan analyse --generate-baseline`; we don't manage its contents.
- `rector.php` — user adds `withSkip` rules per project; same logic.
- `pint.json` — user-tunable rule set; same logic.

For `notify-only` files, audit mentions drift in the report ("`phpstan.neon.dist` has drifted from our stub; review manually") but doesn't push a fix.

## Why this matters

v3 of the spec had a blunt "any diff = OUTDATED" rule, which would create noisy false-positives on files users legitimately customize. v4-onwards split per merge mode so audit signal stays high.

## Bootstrap mode behaviour

In bootstrap, every file is written fresh — merge modes don't apply, just copy from the stub.

Exception: bootstrap of `laravel-project` runs `laravel new` first, which produces some of the same files we'd write (e.g. `.editorconfig`, `phpunit.xml`). For those, bootstrap behaves like upgrade — prompt before overwrite.
